Return to local control after Home Assistant commands

On the validated iSaver Power 1100, a D0 command keeps remote priority for about 60 seconds. A C3 read during that active window prolongs the remote priority. After a true silent handover, later C3 reads do not restore the old D0 setpoint.

Home Assistant command → one D0 / Modbus write → 70 s protected silence by default → physical panel available again → normal polling resumes → later physical-panel changes are detected normally
Return to local controlSwitch. Enabled by default.

Local panel control availableBinary sensor with a hand icon. ON means the handover timer has expired.
WaveShare note. Validation showed that leaving the TCP connection open without sending RS485 traffic does not keep iSaver remote priority active. The decisive factor is pump-protocol traffic during the watchdog window.

FAQ

Aquagem Home Assistant FAQ

Is Return to local control enabled by default?

Yes. New installations use a 70-second protected silence after Home Assistant commands. The delay can be adjusted from 50 to 180 seconds.

What does the hand binary sensor mean?

“Local panel control available” is ON when the protected handover window has expired and the physical panel is expected to be available again.

Does the countdown send RS485 traffic?

No. The countdown is calculated locally inside Home Assistant and does not poll the pump during the protected silence.

Does the integration require the Aquagem cloud?

No. Pump communication remains local.
